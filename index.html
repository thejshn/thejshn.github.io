Case File · 001  ·  SFx – Sora Financial Tech

Product Analytics & Live Metrics, SFx Lite

TypeScript  ·  PostgreSQL  ·  SQL Views  ·  Grafana Cloud  ·  GitHub

Brief

SFx Lite, a fintech product, had users moving through the app but no way to see them. My job: build the analytics layer from nothing, so every number traces back to a real user action.

Build

In four weeks I designed the event taxonomy and tracking pipeline, instrumented the core user flows, and shipped the first product dashboard on Grafana Cloud. Events are validated, stored, and rolled up by SQL views into funnels, cohorts, and KPIs, then extended with admin KYC review tracking and chatbot cost monitoring.

Discovery

The funnel told the story end to end: 23 signups → 15 completed KYC → 7 made a first transaction, a 30% signup-to-first-transaction rate. Weekly cohorts tracked KYC, deposit, and first-transaction rates, while chatbot spend held at about $0.12 to date.

Twist

Then the data caught something nobody had reported. A spike in chatbot failures traced back to a missing API key in the deployed environment. The analytics work had surfaced a live production issue.

Next

The story continues on the main product: I'm now extending the tracking to the SFx Money app.

Case File · 006

The Automated Pipeline

AWS S3  ·  Glue (PySpark)  ·  Lambda  ·  IAM  ·  Docker

The Problem

Raw sales data was being processed manually slow, error-prone, and unscalable. Local deployment limitations blocked automation. A serverless, cloud-native solution was needed.

The Build

Engineered a serverless ETL pipeline on AWS: S3 for storage, Glue with PySpark for transformation, Lambda for orchestration, and IAM for security. Containerised the entire stack with Docker to eliminate deployment friction.

The Result

Raw sales data is now automatically cleaned, standardised, and exported as analytics-ready Parquet files with 70% storage reduction (208 KB → 63 KB) and zero manual intervention.
